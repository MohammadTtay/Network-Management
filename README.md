# پروژه شبیه‌سازی اقتصادی مدیریت شبکه با Python

این پروژه به عنوان یکی از پروژه های درس مدیریت شبکه دوره کارشناسی ارشد انجام شده و یک شبکه فرضی ۱۰ شعبه‌ای را در دو سناریوی **مدیریت سنتی** و **مدیریت هوشمند و پایش خودکار** مقایسه می‌کند.

## قابلیت‌ها

- ایجاد شبکه ۱۰ شعبه‌ای شامل Router، Switch، Firewall، لینک اینترنت، کاربران و ظرفیت پهنای باند
- محاسبه CAPEX شامل Router، Switch، Firewall، کابل‌کشی و نصب
- محاسبه OPEX ماهانه و سالانه بر اساس ریزهزینه‌ها
- محاسبه TCO طی ۵ سال: `TCO = CAPEX + 60 × Monthly OPEX`
- تولید رویدادهای یک ماهه شامل خرابی لینک، خرابی روتر، قطعی فایروال، خطای پیکربندی، ترافیک بالا، مصرف بیش از حد پهنای باند، افزایش کاربران و گلوگاه
- مقایسه زمان تشخیص، عیب‌یابی، تعمیر، Downtime، درآمد ازدست‌رفته و Availability
- تشخیص گلوگاه با آستانه هشدار ۹۰٪
- تحلیل ترافیک Branch-5 و انتقال زمان Backup از ساعت ۱۰ به ۲ بامداد
- پیش‌بینی روند مصرف Branch-3 و برآورد روز اشباع ظرفیت با رگرسیون خطی ساده
- ساخت چهار نمودار اصلی خواسته‌شده در صورت پروژه و یک نمودار تکمیلی پیش‌بینی
- تولید گزارش نهایی متنی و فایل‌های CSV/JSON

## روش اجرا

به Python 3.10 یا جدیدتر نیاز است.

```bash
python -m venv .venv
```

فعال‌سازی محیط مجازی در Windows:

```powershell
.venv\Scripts\activate
```

فعال‌سازی در Linux/macOS:

```bash
source .venv/bin/activate
```

نصب کتابخانه‌ها:

```bash
pip install -r requirements.txt
```

اجرای پروژه با داده‌های قابل‌بازتولید:

```bash
python network_management_simulation.py
```

اجرای پروژه با بذر تصادفی دیگر:

```bash
python network_management_simulation.py --seed 7 --output-dir output_seed7
```

با بذر پیش‌فرض ۴۲، داده‌های تصادفی هر بار یکسان تولید می‌شوند. برای تولید نمونه جدید، مقدار `--seed` را تغییر دهید.

## فرض‌ها و نکات تفسیری

چون صورت پروژه برای همه مقادیر ورودی، قیمت‌ها و توزیع تصادفی جزئیات تعیین نکرده است، فرض‌های زیر برای کامل‌کردن شبیه‌سازی انتخاب شده‌اند و در کد قابل تغییرند:

1. **بذر تصادفی:** مقدار پیش‌فرض ۴۲ است. تعداد کاربران، مقادیر مصرف ترافیک، روز و تخصیص بیشتر رویدادها به شعبه‌ها و داده‌های تاریخچه پیش‌بینی با مولد تصادفی ساخته می‌شوند؛ در نتیجه خروجی با بذر یکسان قابل بازتولید است.
2. **هزینه تجهیزات پایه:** جمع قیمت‌های ۱۰ روتر ۵٬۸۰۰ دلار، سوئیچ‌ها ۳٬۴۰۰ دلار و فایروال‌ها ۴٬۲۰۰ دلار است. برای جداکردن اقلام کابل و نصب، از ۶۰۰ دلار کابل‌کشی و ۱٬۴۰۰ دلار نصب استفاده شده است؛ CAPEX پایه ۱۵٬۴۰۰ دلار می‌شود.
3. **هزینه‌های عملیاتی:** صورت تمرین هزینه دقیق هر ردیف را مشخص نکرده است. ریزهزینه‌های نمونه در کد طوری تعیین شده‌اند که OPEX سالانه سنتی ۳۸٬۰۰۰ دلار و OPEX سالانه هوشمند ۲۵٬۰۰۰ دلار شود؛ این‌ها **فرض هزینه‌ای مدل** هستند، نه داده بازار یا خروجی تصادفی.
4. **زمان خرابی:** برای هر یک از چهار رخداد قطعی‌زا (خرابی لینک، روتر، فایروال و خطای پیکربندی)، از زمان‌های صریح بخش مدیریت سنتی و هوشمند صورت پروژه استفاده می‌شود: سنتی ۳۰+۶۰+۹۰=۱۸۰ دقیقه و هوشمند ۲+۵+۳۰=۳۷ دقیقه. سایر رویدادها هشدار/تغییر عملیاتی محسوب شده و قطعی کامل به آن‌ها نسبت داده نمی‌شود. بنابراین برای چهار خرابی، Downtime جمعی ۷۲۰ و ۱۴۸ دقیقه خواهد بود.
5. **Availability:** طبق مثال انتهایی صورت تمرین محاسبه می‌شود: `(دقایق دوره ۳۰ روزه - مجموع دقایق قطعی رخدادها) / دقایق دوره × 100`. این تعریف، برای سازگاری با نمونه‌جدول تمرین به کار رفته است؛ در شبکه واقعی با خرابی شعبه‌های جداگانه ممکن است لازم باشد دسترس‌پذیری هر شعبه جداگانه محاسبه و سپس تجمیع شود.
6. **درآمد ازدست‌رفته:** طبق صورت پروژه، ۱۰۰ دلار به ازای هر دقیقه Downtime در نظر گرفته شده است.
7. **گلوگاه و خرید ارتقا:** آستانه ۹۰٪ استفاده می‌شود. برای بخش تصمیم‌گیری اقتصادی، هر شعبه‌ای که از این آستانه عبور کند یک تصمیم ارتقای ۶۰۰ دلاری را فعال می‌کند. پس از انتقال Backup شعبه ۵، تصمیم‌های ارتقا دوباره محاسبه می‌شوند. این شمارنده یک **مدل ساده تصمیم خرید** است، نه اثبات اینکه هر ارتقا در دنیای واقعی غیرضروری است.
8. **پیش‌بینی:** روند مصرف ۲۲ روز داده مصنوعی با رگرسیون خطی ساده برازش می‌شود و زمان رسیدن روند به ظرفیت ۱۰۰ Mbps برآورد می‌شود. این پیش‌بینی آموزشی است و نباید به‌عنوان پیش‌بینی عملیاتی واقعی تفسیر شود.
9. **مقدارهای نمونه در جدول پایانی PDF:** آن اعداد، طبق خود داک، نمونه‌اند. برنامه مقادیر را از داده‌ها و فرض‌های مدل محاسبه می‌کند؛ بنابراین ممکن است برخی اعداد با جدول نمونه یکی نباشند، به‌خصوص چون روش زمان تعمیر در بخش ششم با Mean Repair Time جدول نمونه متفاوت است.
